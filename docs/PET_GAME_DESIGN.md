## 1. 一句话概括

两个人共同养育一只**小宠物**，住在一个**可以装修的小窝**里。宠物的状态和成长完全由你们的日常积分行为驱动——签到、记分、写情书都会让它长大、变开心；冷落它，它会闷闷不乐。赚到的积分除了换奖励，还能买**家具、衣服、装饰**，把小窝布置成你们喜欢的样子。

**为什么这个玩法值得做：** 现在的应用是「记账式」的——记录、结算、清零。它缺少一个**看得见的、持续累积的东西**。宠物和小窝就是那个东西：它不会每月清零，它会一直长大，是你们关系的可视化身。这正是让应用「不无聊」的关键。

## 2. 核心循环 (Core Loop)

```
        日常行为                      宠物反馈                  长期奖励
   ┌────────────────┐          ┌────────────────┐      ┌────────────────┐
   │  签到 / 记分    │  ──→     │ 心情 ↑ 经验 ↑   │ ──→  │  升级 / 进化    │
   │  情书 / 回忆    │          │ 动画 / 说话     │      │  解锁新家具     │
   └────────────────┘          └────────────────┘      └────────────────┘
            │                                                    │
            └──────────  积分 → 商店买家具/衣服  ←────────────────┘
```

一天的体验应该是：打开 App → 小窝里的宠物跑过来打招呼 → 看到它今天的心情和一句话 → 顺手签到 / 记一笔 → 宠物变开心、经验条动一下 → 偶尔攒够分，去买个新沙发。

## 3. 宠物系统

### 3.1 宠物是什么

**建议：一只「你们两个的孩子」概念的小生物**，而不是猫狗——因为它应该属于「我们」，不属于某一个人。视觉上延续现有的线条小狗风格（白色 + 粉色的圆润角色）。

命名：进入游戏时让你们给它取名字（存在配置里）。

### 3.2 成长阶段 (Evolution)

宠物按**经验值 EXP** 成长，经验来自你们的日常行为（见 3.4）。

| 阶段 | 名称 | 所需 EXP | 外观概念 |
|---|---|---|---|
| 1 | 🥚 蛋蛋期 | 0 | 一颗会晃动的蛋，偶尔裂一点缝 |
| 2 | 🐣 幼崽期 | 300 | 刚破壳，圆滚滚，头上有蛋壳 |
| 3 | 🐶 成长期 | 1,000 | 站起来了，会跑会跳 |
| 4 | 🐕 活泼期 | 2,500 | 更大只，会做小动作（打滚、追尾巴） |
| 5 | 👑 圆满期 | 6,000 | 戴皇冠，有光环特效 |

> **重点：EXP 只增不减，永不清零。** 月末结算清零的是积分，不是宠物。这样宠物才是你们关系的长期见证。

### 3.3 心情系统 (Mood)

心情是**短期**状态，0–100，反映你们**最近**的活跃度：

- 每天自然衰减 −8
- 任一方签到 +10，双方都签到额外 +5
- 记一条加分 +5（每天最多累计 +20）
- 写一封情书 +15
- 添加一张回忆照片 +10
- 扣分记录 −10

| 心情 | 表情 | 宠物状态 |
|---|---|---|
| 80–100 | 🤩 超开心 | 蹦蹦跳跳，有爱心特效 |
| 50–79 | 🙂 开心 | 正常呼吸动画，偶尔眨眼 |
| 20–49 | 😐 一般 | 动作变慢，耳朵下垂 |
| 0–19 | 🥺 想你们了 | 蜷缩着，头顶小雨云 |

心情低时，主页 banner 会提醒：「小窝里的 ○○ 有点想你们了 🥺」——这是**召回机制**，也是让两个人互相催对方开 App 的社交动力。

### 3.4 EXP 来源（复用现有数据，不需要新逻辑）

| 行为 | EXP |
|---|---|
| 每日签到 | +10（周日 +20） |
| 记一条加分记录 | +5 |
| 写一封情书 | +30 |
| 添加一张回忆照片 | +20 |
| 完成月末结算 | +100 |
| 达成共同目标 | +300 |

这些行为**你们已经在做了**——所以宠物一上线就会立刻从现有历史数据里「追认」经验，不会是空的。这点很重要：新功能上线第一眼就该有内容。

### 3.5 宠物的一句话 (Pet Speech)

每次打开小窝，宠物头顶冒一句话泡泡。根据情境从池子里随机抽：

- 心情高：「今天也好幸福呀～」「你们两个最好了！」
- 心情低：「好久没人陪我了…」「爸爸妈妈去哪了？」
- 刚签到：「谢谢你来看我！」
- 快升级：「我感觉…我快要长大了！」
- 纪念日：「今天是特别的日子哦 🎂」

这个池子放在前端常量里就好，不占后端。

## 4. 小窝装修系统

### 4.1 房间视图

一个 **2.5D 侧视房间**（不做 3D，用 CSS + 分层图片就够了）：

```
┌─────────────────────────────────────┐
│  🖼 挂画        窗户 🪟              │  ← 墙面层 (wall)
│                                      │
│      🌱          [宠物]        🛋    │  ← 家具层 (floor items)
│   ┌──────────────────────────────┐  │
│   │        地板 / 地毯            │  │  ← 地板层 (floor)
│   └──────────────────────────────┘  │
└─────────────────────────────────────┘
     [🛍 商店]  [🎽 换装]  [📦 收纳]
```

**分层结构（决定了实现难度）：**

| 层 | 内容 | 同时可放 |
|---|---|---|
| 背景/墙纸 | 墙面样式 | 1 |
| 地板 | 地板样式 | 1 |
| 墙面装饰 | 挂画、窗户、时钟 | 3 个槽位 |
| 地面家具 | 沙发、桌子、植物、灯 | 4 个槽位 |
| 宠物 | 主角，站在中间 | 1 |
| 宠物穿戴 | 帽子 / 衣服 / 配饰 | 各 1 |

**用槽位 (slots) 而不是自由拖拽** —— 这是关键的简化决策。自由拖拽要处理坐标、层级、碰撞、不同屏幕适配，工作量翻好几倍；槽位制体验依然很好，实现量只有一半。以后想升级成拖拽也不难。

### 4.2 物品从哪来

**复用现有商店系统**，加一个 `type` 区分：

- `type = 'real'` → 现在的现实奖励（奶茶、按摩券）
- `type = 'decor'` → 家具 / 装饰 / 衣服（虚拟物品）

这样**不用新建商店表**，买东西的扣分、背包、历史逻辑全部复用。只是虚拟物品买了之后不是「使用」，而是「放进小窝 / 穿上」。

### 4.3 初始物品清单（内置，不用你们自己建）

| 类别 | 物品 | 价格 |
|---|---|---|
| 🛋 家具 | 小沙发 / 双人床 / 餐桌 / 书架 | 60–150 |
| 🌱 装饰 | 绿植 / 落地灯 / 相框 / 鱼缸 | 40–100 |
| 🖼 墙面 | 全家福挂画 / 时钟 / 星空窗 | 50–120 |
| 🎨 墙纸 | 奶油白 / 樱花粉 / 星空蓝 | 80 |
| 🪵 地板 | 木地板 / 地毯 / 瓷砖 | 80 |
| 🎽 衣服 | 睡衣 / 毛衣 / 生日帽 / 墨镜 | 30–90 |
| ✨ 限定 | 情人节礼服 / 圣诞装 / 周年皇冠 | 成就解锁，不卖 |

**限定物品用成就解锁**（例如「坚持一年」送周年皇冠）——把刚做好的成就系统和这个玩法打通，两个功能互相加分。


### 5.2 小窝页面（全屏，从右滑入，和情书/商店一致）

- 顶部：宠物名字、等级、经验条
- 中间：房间视图（见 4.1），宠物有呼吸/眨眼的循环动画
- 点宠物：它会有反应（跳一下 + 冒一句话 + 心情 +1，每天限 3 次）
- 底部三个按钮：**🛍 装饰商店** / **🎽 换装** / **📦 我的收纳**

### 5.3 视觉风格建议

延续现有的柔和风格，但房间要有**光影层次**才「像真的」：

- 墙面用微弱的垂直渐变（上暗下亮）模拟环境光
- 家具加一点 `drop-shadow` 落在地板上
- 窗户根据**真实时间**变化：白天蓝天 ☀️、傍晚橘色 🌇、夜晚星空 🌙 —— 和你们已有的日夜主题联动，成本很低但效果惊艳 ✅ **已实现（第一期）**
- 宠物用 CSS 动画（呼吸 = scale 循环，眨眼 = 定时切换眼睛路径），和现有的线条小狗 SVG 同一套做法

## 5.5 🍂 季节 / 节日主题（新增想法）

> 目标：让小窝**跟着真实世界走**，一年四季不一样，打开时会有「诶，换季了」的惊喜感。

### ⚠️ 先要决定的一件事：你们那边没有四季

时区是 UTC+8（马来西亚 / 新加坡一带），**春夏秋冬对你们的生活没有实感** —— 十二月不会下雪，四月也没有樱花。所以直接照搬「四季」可能反而假。

两条路线（也可以混着用，我推荐混合）：

| 路线 | 内容 | 适合度 |
|---|---|---|
| **A. 节日主题**（推荐主线） | 农历新年 🧧、情人节 💐、端午、中秋 🥮、开斋节 🌙、屠妖节 🪔、圣诞 🎄、跨年 🎆 | ⭐⭐⭐⭐⭐ 对你们最有实感，而且节日本来就是情侣会一起过的日子 |
| **B. 四季主题**（辅线／氛围） | 樱花春、清凉夏、枫叶秋、雪景冬 | ⭐⭐⭐ 没实感，但作为「换个心情」的装饰主题依然好看，可当成商店里买得到的皮肤 |

**建议做法：节日优先，四季兜底。** 平时按四季轮换氛围（纯装饰、无实感也无所谓），一到节日窗口就**自动覆盖**成节日主题——节日才是真正会让你们「哇」一下的时刻。

### 季节主题会改变什么

一个主题 = 一组同时切换的东西，不是只换个背景色：

| 层 | 例子（以中秋为例） |
|---|---|
| 🪟 窗外景色 | 满月 + 云 |
| 🎨 墙面 / 地板色调 | 暖橘 + 深木色 |
| ❄️ 环境粒子 | 飘落的桂花瓣 |
| 🧸 宠物穿戴 | 自动戴上小兔耳朵 / 提灯笼 |
| 🛋 商店上架 | 限定家具：灯笼、月饼桌、竹席 |
| 💬 宠物台词 | 「今晚月亮好圆呀，一起看嘛？」 |

**「宠物会说节日相关的话」是性价比最高的一条** —— 一行文案，但会让它显得真的活在这个世界里。

### 实现方式（关键：不增加你的后端工作）

季节完全由**日期在前端算出来**，不存数据库、不需要新表、不需要新 API：

```js
// 一个数据驱动的表，加新节日 = 加一个对象
const THEMES = [
  { id:'cny',    name:'新年',   from:'01-25', to:'02-10', priority:10, ... },
  { id:'midaut', name:'中秋',   from:'09-10', to:'09-20', priority:10, ... },
  { id:'xmas',   name:'圣诞',   from:'12-18', to:'12-27', priority:10, ... },
  { id:'spring', name:'春',     from:'03-01', to:'05-31', priority:1,  ... },
  // …priority 高的覆盖低的
];
```

- 农历节日（新年、中秋、端午）**日期每年不同** → 需要一张未来几年的日期对照表（几行常量，比引入农历库划算得多）
- 主题只影响**外观**，不影响积分逻辑，所以出错也不会弄坏数据
- 限定家具就是目录里带 `availableFrom / availableTo` 的普通商品，**过季自动下架**，制造「今年不买就要等明年」的稀缺感

### 设计风格跟上潮流

你提到希望家具和主题的设计「跟着趋势」。现在这类养成 / 装修游戏视觉上流行的是：

- **柔和 3D / 黏土感（claymorphism）** —— 圆角、厚实、柔和投影，像捏出来的。用 SVG 渐变 + 多层阴影就能仿出来，不用真 3D
- **低饱和奶油色系** —— 米白、奶茶、雾霾蓝，而不是高饱和的原色（你们现在的配色已经挺接近了）
- **柔和环境光 + 长投影** —— 让平面的东西有空间感，这是「看起来贵」的关键
- **微互动** —— 点一下有回弹、悬停会微微浮起

参考感觉：《动物森友会》的房间、Cocoon / Alto 系列的柔和光影、iOS 小组件那种圆润厚重感。

> 建议：**主题按季度更新一次**就够了，不用追太紧。每次换季顺手把当季家具重画一版，比一次性做一堆更容易维持。

### 分期建议

季节主题属于**第三期**（润色期）。理由：先有宠物和基础装修，季节才有东西可以「换」；否则只是换个背景色，感受不到。

但有一个例外值得**提前到第一期之后马上做**：**节日台词 + 节日自动穿戴**。两者几乎零成本，却是「像真的」感受最强的部分。

## 6. 数据设计

### 6.1 不需要新表 ✅（比原计划更省）

原本打算建 `u_love_pet` 表，**实际实现时改成挂在现有的 `u_love_config` 那一行上** —— 因为共同目标本来就要改 r01/r02，顺路把宠物字段一起加，等于宠物的后端成本 = 0 个新表 + 0 个新资源。

`u_love_config` 上加的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| u_pet_name | String(40) | 宠物名字 |
| u_pet_species | String(20) | `dog` / `cat` / `bunny` / `baby` |
| u_pet_exp | Integer | 经验**保底值**（只增不减，见下） |
| u_pet_equipped | String(1000) | JSON 装备状态，第二期才用（先建好，省得再回 SN 一趟） |

**等级和心情都不存**，每次打开现算：

- **EXP** = 两人累计积分（已结算 + 本轮）+ 情书 ×30 + 回忆 ×20 + 结算月数 ×100
- **心情** = 只看最近 3 天的活跃度，自然衰减、自然回升，不需要定时任务

> **为什么还要存一个 EXP 保底值？**
> 算出来的 EXP 在两种情况下会「倒退」：① 惩罚模式的月份结算时存的是负分，那个月赚的正分就找不回来了；② 删掉旧照片 / 情书会把它的经验一起扣掉。
> 宠物**绝对不能变小**，所以额外存一个历史最高值，显示时取 `max(算出来的, 存的)`，而且 r02 会**拒绝任何调低它的写入**。双保险。

### 6.2 物品目录放哪

**放在前端代码里（常量）**，不进数据库。原因：

- 物品是设计资产（图标、价格、槽位），不是用户数据
- 改价格 / 加新家具 / 上架季节限定 = 改一行代码 + push，**不用碰 SN**
- 用户拥有的物品记录在**已有的 `u_love_bag` 表**里，加个 `u_source_type = 'decor'` 就行

这一点对「每周维护」很关键（见 §10）：日常更新主题和家具**不需要动数据库，只改前端**。

## 7. 🔁 长期维护节奏（每周 / 每季）

> 你提到希望能**定期更新设计和主题**。这是对的——养成类玩法最怕的就是「三个月后没东西看了」。但节奏要选得可持续，不然自己先累垮。

### 建议节奏：小步快跑

| 频率 | 做什么 | 花的时间 |
|---|---|---|
| **每周** | 微调：加几句宠物新台词、修小 bug、调一下颜色/间距 | 10–20 分钟 |
| **每月** | 上架 2–3 件新家具 / 新衣服；看一下数据（你们真的在用哪些功能） | 半小时 |
| **每季 / 每节日** | 换季节主题：窗景、墙纸地板、限定家具、节日台词 | 1–2 小时 |
| **每年** | 大版本：新玩法（小游戏、新槽位、宠物新阶段） | 看心情 |

**每周那一档最重要**，因为它成本最低但最能维持「这个 App 还活着」的感觉。哪怕只是多加三句台词，打开时看到没见过的话就会觉得新鲜。

### 让「每周更新」真的做得动的前提（设计上要先铺好）

1. **所有可变内容都是数据，不是代码逻辑** —— 台词池、家具目录、主题表都是数组/对象，加东西 = 加一条，不用改逻辑、不怕改坏
2. **不碰 ServiceNow** —— 前端改完 push 就生效（GitHub Pages 自动部署），不用你手动去贴脚本
3. **过季自动下架** —— 家具带 `availableFrom/To`，不用手动管理上下架
4. **向后兼容** —— 已经买了的季节限定家具，过季后**照样能用**，只是买不到了

### 维护清单模板（每次更新照着走）

```
□ 加 2–5 句新台词（挑当季/当下心情的）
□ 上架 1–3 件当季家具（带 availableFrom/To）
□ 检查下一个节日日期对不对（农历要查表）
□ 手机上真机看一眼浅色 + 深色
□ bump APP_VERSION，push
```

> 我可以在你想更新的时候直接照这个清单帮你做——你只要说「换成中秋主题」，剩下的交给我。

## 9. 已确定的设计决策 ✅

| 问题 | 决定 | 实现情况 |
|---|---|---|
| 宠物形态 | **可以选**，先做宠物 | ✅ 4 种：小狗 / 小猫 / 小兔 / 宝宝 |
| 叫法 | 先用「主人」，且**跟着选择自动变** | ✅ 动物→主人，宝宝→爸爸妈妈；以后加新形态自动套用 |
| 美术 | 要好看、要能随时间慢慢长大 | ✅ **SVG 矢量**（几 KB、不糊、无需素材托管）；每阶段一套画，阶段内跟着 EXP 平滑放大 |
| 装修自由度 | 槽位制 | 待第二期 |
| 竞争元素 | **可以显示，但不影响** | ✅ 显示「本轮一起投喂」占比，纯展示 |
| 季节主题 | 要跟着季节 / 潮流更新 | 待第三期（§5.5） |
| 维护节奏 | 定期更新设计与主题 | 见 §7 |

### 实现时改掉的两个原设计（都是为了少让你动 SN）

1. **不建 `u_love_pet` 表** → 字段挂在 `u_love_config` 上，省掉 1 张表 + 2 个资源
2. **心情不落库** → 改成从最近 3 天活跃度实时算，省掉 `u_mood` / `u_mood_date` 两个字段和每日衰减逻辑

### 实现时发现并修掉的坑（记录下来避免重犯）

- **月末结算会让宠物缩小**：惩罚模式月份存的是负分 → 加了 EXP 保底值 + 服务端拒绝调低
- **狗的耳朵看不见**：耳朵画在头的椭圆下面被完全盖住，四种宠物长得一模一样 → 耳朵必须画在头部轮廓**外面**
- **皇冠盖住耳朵**：尖耳/长耳正好在皇冠位置 → 改成悬浮光环
- **地板挡住宠物**：`::after` 会画在兄弟元素**上面**，挡住下半身还吃掉点击 → 显式 `z-index` + `pointer-events:none`
