# 🏡 恋爱小窝 (Love Nest) — 养成 + 装修玩法设计稿

> Status: **设计中 / Design draft — not implemented yet.**
> 这份文档是我们一起讨论的蓝图。先把玩法、数据、分期都定下来，再动手写代码。

---

## 1. 一句话概括

两个人共同养育一只**小宠物**，住在一个**可以装修的小窝**里。宠物的状态和成长完全由你们的日常积分行为驱动——签到、记分、写情书都会让它长大、变开心；冷落它，它会闷闷不乐。赚到的积分除了换奖励，还能买**家具、衣服、装饰**，把小窝布置成你们喜欢的样子。

**为什么这个玩法值得做：** 现在的应用是「记账式」的——记录、结算、清零。它缺少一个**看得见的、持续累积的东西**。宠物和小窝就是那个东西：它不会每月清零，它会一直长大，是你们关系的可视化身。这正是让应用「不无聊」的关键。

---

## 2. 核心循环 (Core Loop)

```
        日常行为                      宠物反馈                  长期奖励
   ┌────────────────┐          ┌────────────────┐      ┌────────────────┐
   │  签到 / 记分    │  ──→     │ 心情 ↑ 经验 ↑   │ ──→  │  升级 / 进化    │
   │  情书 / 回忆    │          │ 动画 / 说话     │      │  解锁新家具     │
   └────────────────┘          └────────────────┘      └────────────────┘
            │                                                    │
            └──────────  积分 → 商店买家具/衣服  ←────────────────┘
```

一天的体验应该是：打开 App → 小窝里的宠物跑过来打招呼 → 看到它今天的心情和一句话 → 顺手签到 / 记一笔 → 宠物变开心、经验条动一下 → 偶尔攒够分，去买个新沙发。

## 3. 宠物系统

### 3.1 宠物是什么

**建议：一只「你们两个的孩子」概念的小生物**，而不是猫狗——因为它应该属于「我们」，不属于某一个人。视觉上延续现有的线条小狗风格（白色 + 粉色的圆润角色）。

命名：进入游戏时让你们给它取名字（存在配置里）。

### 3.2 成长阶段 (Evolution)

宠物按**经验值 EXP** 成长，经验来自你们的日常行为（见 3.4）。

| 阶段 | 名称 | 所需 EXP | 外观概念 |
|---|---|---|---|
| 1 | 🥚 蛋蛋期 | 0 | 一颗会晃动的蛋，偶尔裂一点缝 |
| 2 | 🐣 幼崽期 | 300 | 刚破壳，圆滚滚，头上有蛋壳 |
| 3 | 🐶 成长期 | 1,000 | 站起来了，会跑会跳 |
| 4 | 🐕 活泼期 | 2,500 | 更大只，会做小动作（打滚、追尾巴） |
| 5 | 👑 圆满期 | 6,000 | 戴皇冠，有光环特效 |

> **重点：EXP 只增不减，永不清零。** 月末结算清零的是积分，不是宠物。这样宠物才是你们关系的长期见证。

### 3.3 心情系统 (Mood)

心情是**短期**状态，0–100，反映你们**最近**的活跃度：

- 每天自然衰减 −8
- 任一方签到 +10，双方都签到额外 +5
- 记一条加分 +5（每天最多累计 +20）
- 写一封情书 +15
- 添加一张回忆照片 +10
- 扣分记录 −10

| 心情 | 表情 | 宠物状态 |
|---|---|---|
| 80–100 | 🤩 超开心 | 蹦蹦跳跳，有爱心特效 |
| 50–79 | 🙂 开心 | 正常呼吸动画，偶尔眨眼 |
| 20–49 | 😐 一般 | 动作变慢，耳朵下垂 |
| 0–19 | 🥺 想你们了 | 蜷缩着，头顶小雨云 |

心情低时，主页 banner 会提醒：「小窝里的 ○○ 有点想你们了 🥺」——这是**召回机制**，也是让两个人互相催对方开 App 的社交动力。

### 3.4 EXP 来源（复用现有数据，不需要新逻辑）

| 行为 | EXP |
|---|---|
| 每日签到 | +10（周日 +20） |
| 记一条加分记录 | +5 |
| 写一封情书 | +30 |
| 添加一张回忆照片 | +20 |
| 完成月末结算 | +100 |
| 达成共同目标 | +300 |

这些行为**你们已经在做了**——所以宠物一上线就会立刻从现有历史数据里「追认」经验，不会是空的。这点很重要：新功能上线第一眼就该有内容。

### 3.5 宠物的一句话 (Pet Speech)

每次打开小窝，宠物头顶冒一句话泡泡。根据情境从池子里随机抽：

- 心情高：「今天也好幸福呀～」「你们两个最好了！」
- 心情低：「好久没人陪我了…」「爸爸妈妈去哪了？」
- 刚签到：「谢谢你来看我！」
- 快升级：「我感觉…我快要长大了！」
- 纪念日：「今天是特别的日子哦 🎂」

这个池子放在前端常量里就好，不占后端。

## 4. 小窝装修系统

### 4.1 房间视图

一个 **2.5D 侧视房间**（不做 3D，用 CSS + 分层图片就够了）：

```
┌─────────────────────────────────────┐
│  🖼 挂画        窗户 🪟              │  ← 墙面层 (wall)
│                                      │
│      🌱          [宠物]        🛋    │  ← 家具层 (floor items)
│   ┌──────────────────────────────┐  │
│   │        地板 / 地毯            │  │  ← 地板层 (floor)
│   └──────────────────────────────┘  │
└─────────────────────────────────────┘
     [🛍 商店]  [🎽 换装]  [📦 收纳]
```

**分层结构（决定了实现难度）：**

| 层 | 内容 | 同时可放 |
|---|---|---|
| 背景/墙纸 | 墙面样式 | 1 |
| 地板 | 地板样式 | 1 |
| 墙面装饰 | 挂画、窗户、时钟 | 3 个槽位 |
| 地面家具 | 沙发、桌子、植物、灯 | 4 个槽位 |
| 宠物 | 主角，站在中间 | 1 |
| 宠物穿戴 | 帽子 / 衣服 / 配饰 | 各 1 |

**用槽位 (slots) 而不是自由拖拽** —— 这是关键的简化决策。自由拖拽要处理坐标、层级、碰撞、不同屏幕适配，工作量翻好几倍；槽位制体验依然很好，实现量只有一半。以后想升级成拖拽也不难。

### 4.2 物品从哪来

**复用现有商店系统**，加一个 `type` 区分：

- `type = 'real'` → 现在的现实奖励（奶茶、按摩券）
- `type = 'decor'` → 家具 / 装饰 / 衣服（虚拟物品）

这样**不用新建商店表**，买东西的扣分、背包、历史逻辑全部复用。只是虚拟物品买了之后不是「使用」，而是「放进小窝 / 穿上」。

### 4.3 初始物品清单（内置，不用你们自己建）

| 类别 | 物品 | 价格 |
|---|---|---|
| 🛋 家具 | 小沙发 / 双人床 / 餐桌 / 书架 | 60–150 |
| 🌱 装饰 | 绿植 / 落地灯 / 相框 / 鱼缸 | 40–100 |
| 🖼 墙面 | 全家福挂画 / 时钟 / 星空窗 | 50–120 |
| 🎨 墙纸 | 奶油白 / 樱花粉 / 星空蓝 | 80 |
| 🪵 地板 | 木地板 / 地毯 / 瓷砖 | 80 |
| 🎽 衣服 | 睡衣 / 毛衣 / 生日帽 / 墨镜 | 30–90 |
| ✨ 限定 | 情人节礼服 / 圣诞装 / 周年皇冠 | 成就解锁，不卖 |

**限定物品用成就解锁**（例如「坚持一年」送周年皇冠）——把刚做好的成就系统和这个玩法打通，两个功能互相加分。

## 5. 页面设计

### 5.1 入口

底部导航已经 5 个满了。建议：**主页的宠物 banner** —— 显示宠物缩略图 + 心情 + 一句话，点进去是小窝全屏页。放在「共同目标」卡片下面。

```
┌────────────────────────────────────┐
│ 🐣  豆豆   Lv.2  ▓▓▓▓▓░░░ 320/1000 │
│     「今天也好幸福呀～」        ›   │
└────────────────────────────────────┘
```

### 5.2 小窝页面（全屏，从右滑入，和情书/商店一致）

- 顶部：宠物名字、等级、经验条
- 中间：房间视图（见 4.1），宠物有呼吸/眨眼的循环动画
- 点宠物：它会有反应（跳一下 + 冒一句话 + 心情 +1，每天限 3 次）
- 底部三个按钮：**🛍 装饰商店** / **🎽 换装** / **📦 我的收纳**

### 5.3 视觉风格建议

延续现有的柔和风格，但房间要有**光影层次**才「像真的」：

- 墙面用微弱的垂直渐变（上暗下亮）模拟环境光
- 家具加一点 `drop-shadow` 落在地板上
- 窗户根据**真实时间**变化：白天蓝天 ☀️、傍晚橘色 🌇、夜晚星空 🌙 —— 和你们已有的日夜主题联动，成本很低但效果惊艳
- 宠物用 CSS 动画（呼吸 = scale 循环，眨眼 = 定时切换眼睛路径），和现有的线条小狗 SVG 同一套做法

## 6. 数据设计

### 6.1 需要的新表：只有一张

**`u_love_pet`** — 一个 couple 一行

| 字段 | 类型 | 说明 |
|---|---|---|
| u_name | String(40) | 宠物名字 |
| u_exp | Integer | 累计经验，只增不减 |
| u_mood | Integer | 心情 0–100 |
| u_mood_date | String(10) | 上次心情结算日期（用来算每日衰减） |
| u_equipped | String(1000) | JSON：`{"wall":"w1","floor":"f2","furniture":["s1","p3"],"outfit":"o2"}` |
| u_match | Reference | couple 隔离，和其他表一样 |

> **用一个 JSON 字段存装备状态**，而不是给每个槽位建字段——这样以后加新槽位（比如「宠物玩具」）完全不用改表结构，也不用你再去 SN 加字段。这是特意为了减少你的手工操作。

### 6.2 物品目录放哪

**放在前端代码里（常量）**，不进数据库。原因：

- 物品是设计资产（图标、价格、槽位），不是用户数据
- 改价格 / 加新家具 = 改一行代码 + push，不用碰 SN
- 用户拥有的物品记录在**已有的 `u_love_bag` 表**里，加个 `u_source_type = 'decor'` 就行

### 6.3 需要的 API

| # | Method | Path | 说明 |
|---|---|---|---|
| 40 | GET | `/pet` | 读宠物状态（自动结算心情衰减 + 从历史数据算 EXP） |
| 41 | PUT | `/pet` | 改名字 / 保存装备 / 加心情 |

**只有 2 个新资源。** 买东西复用 `/shop/buy`，拥有的物品复用 `/bag`。

## 7. 分期计划（建议这样做）

### 🥇 第一期：宠物本体（最小可玩）
- `u_love_pet` 表 + 2 个 API
- 主页宠物 banner
- 小窝页面：宠物 + 固定的默认房间（不能装修）
- EXP / 等级 / 心情 / 说话
- **从现有历史数据追认 EXP**，一上线就有等级

> 这一期做完，宠物就已经「活」了。可以先玩一阵子，看看你们真实的感受，再决定装修要做多细。

### 🥈 第二期：装修
- 物品目录（前端常量）+ 商店 `decor` 分类
- 房间分层渲染 + 槽位替换
- 收纳（背包里的 decor 物品）

### 🥉 第三期：润色
- 时间联动的窗户（白天/夜晚）
- 成就解锁限定装扮
- 纪念日彩蛋（生日帽自动出现）
- 点宠物的互动反馈

## 8. 需要你决定的事 🤔

在开始写代码前，这几个问题需要你拍板：

1. **宠物形态**：延续线条小狗风格的「蛋 → 幼崽 → 小狗」，还是想要别的（小猫 / 小熊 / 抽象生物）？
2. **叫法**：叫「宠物」还是「宝宝」？会影响文案语气（「爸爸妈妈」vs「主人」）。
3. **美术**：宠物和家具用 **emoji + CSS**（免费、马上能做、风格统一但不够精致），还是你想找/画 **图片素材**（更好看，但要准备素材）？
   - 我的建议：**第一期先用 emoji + CSS 做出手感**，玩起来觉得对了，再逐步替换成真正的插画。
4. **装修自由度**：接受**槽位制**（我推荐）还是一定要**自由拖拽**？
5. **要不要竞争元素**：比如「谁贡献的 EXP 多」显示出来？还是纯粹合作、不分你我？（我倾向纯合作——你们已经有积分在比了，宠物应该是共同的。）

---

## 9. 我的建议排序

如果想让应用「立刻不无聊」，投入产出比最高的顺序是：

1. **宠物第一期**（本文档 §7 第一期）—— 一个会长大的东西，是最强的长期动力
2. **每日猜心小游戏** —— 每天一个新话题，制造对话
3. **装修第二期** —— 有了宠物之后，装修才有意义
